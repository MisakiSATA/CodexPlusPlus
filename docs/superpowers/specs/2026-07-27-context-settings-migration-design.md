# Codex++ 上下文设置迁移与兼容设计

## 目标

修复 Codex++ 管理器“工具与插件”页面无法显示旧供应商配置中 MCP、Skills、Plugins 的问题，并把当前修复重构为职责独立、可重复执行、可安全持久化的内部模块。完成后构建并安装到当前 Linux 用户级 Codex++ 环境，通过运行时检查确认生效。

## 范围

本次包含：

- 从旧供应商 `configContents` 和旧通用配置迁移上下文表；
- 全局上下文配置的合并和冲突优先级；
- 所有供应商上下文选择的同步；
- 增量保存时清理旧配置副本，防止已删除条目复活；
- 新版 Codex 中旧版资源缺失时的插件市场兼容回退；
- Rust、注入脚本、前端构建以及实际用户级安装验证。

本次不包含：

- 改变“工具与插件”页面的视觉设计；
- 修改 Codex 官方插件市场数据；
- 推送到官方 upstream；
- 迁移或输出用户的 API Key、认证文件或其他敏感配置。

## 方案

采用独立内部模块方案。新增 `crates/codex-plus-core/src/settings/context.rs`，由 `settings.rs` 调用，但不向 crate 外公开。模块负责上下文配置的识别、提取、合并、选择同步和原始 JSON 的最小化持久化；供应商模型与认证字段的派生仍由现有 relay 配置逻辑负责。

这一边界让 `settings.rs` 只编排完整设置的读取、更新与保存，避免上下文迁移继续散落在大型设置文件中，也防止持久化迁移误用完整 `RelayProfile` 序列化而写入运行时派生字段。

## 数据流

加载或更新设置时按以下顺序处理：

1. 从 `relayCommonConfigContents` 提取 MCP、Skills、Plugins 表，保留其余通用配置。
2. 以 `relayContextConfigContents` 作为权威全局配置。
3. 逐个扫描供应商 `configContents`，移出上下文表并合并到全局配置。
4. 同名条目冲突时保留已有全局条目；旧通用配置和旧供应商配置仅补齐缺失项。
5. 从最终全局配置生成 MCP、Skills、Plugins ID 列表，并同步到所有供应商。
6. 空白默认设置保持 `contextSelectionInitialized = false`；已有初始化状态或曾存在全局条目时允许同步为空，从而正确表达“删除最后一个条目”。
7. 增量保存只更新原始供应商 JSON 中的 `configContents`、`contextSelection` 和 `contextSelectionInitialized`，保留其他原始字段形态。

整个过程必须幂等：相同设置重复加载或保存不会产生重复 TOML 表、选择漂移或条目复活。

## TOML 与错误处理

- 正常 TOML 使用现有 `relay_config` 合并能力，保持结构化合并和全局优先级。
- 空输入规范化为空字符串，非空输入保留单个结尾换行。
- 无法结构化合并时使用现有文本拼接回退，避免因一段历史配置损坏而丢弃其他可恢复内容。
- 识别 `[mcp_servers.<id>]`、`[skills.<id>]`、`[plugins.<id>]` 及对应父表；上下文表结束于下一个非上下文 TOML 表头。
- 不读取、记录或测试真实用户密钥。

## 插件市场兼容

Codex 26.707 已不再提供 `app-server-manager-signals-*` 资源。注入脚本将该资源作为可选模块探测：

- 存在时沿用旧客户端补丁；
- 缺失时为当前兼容版本记录一次 `asset_missing` 跳过状态；
- 后续刷新不再重复加载或产生失败日志；
- 现有 bridge 请求与响应补丁继续承担插件市场回退，不因旧资源缺失而禁用。

## 测试设计

Rust 测试覆盖：

- 旧供应商 MCP/Plugin 迁移到全局配置；
- 旧通用配置中的上下文表迁移；
- 全局配置在同名冲突时优先；
- 多供应商获得一致的上下文选择；
- 空白默认设置不被错误标记为已初始化；
- 删除最后一个全局条目后选择清空且旧条目不复活；
- 增量保存不写入模型、API Key 或 Provider 派生字段；
- 重复规范化结果不变。

注入测试覆盖可选模块加载、缺失状态标记和不使用必选加载路径。最终执行完整 Rust 工作区测试、前端单元测试、类型检查、生产构建和差异检查。

## 安装与验收

1. 构建前记录当前 `~/.local/lib/codex-plus-plus/current` 目标和文件摘要。
2. 将当前 1.2.42 版本目录复制为带时间戳的隐藏备份，不覆盖已有备份。
3. 构建前端和 Rust release，生成项目规定的 Linux 便携包。
4. 使用包内 `install.sh` 安装到用户级 XDG 目录并原子切换 `current`。
5. 验证当前符号链接、二进制摘要、桌面入口和安装清单。
6. 启动安装后的管理器和 Codex++，确认进程使用 `current` 下的新二进制。
7. 检查设置响应中旧插件已出现在全局上下文，检查诊断日志不再循环出现 `plugin_marketplace_request_patch_failed`。
8. 若启动或运行时验收失败，停止新进程并将 `current` 原子切回备份，同时保留构建产物用于排查。

## 成功标准

- “工具与插件”页面能够显示旧供应商配置迁移出的插件、MCP 和技能；
- 切换任意供应商都包含全局上下文条目；
- 删除条目并重新加载后不会恢复；
- 新版 Codex 旧资源缺失不再产生重复失败日志；
- 用户级安装运行的是本次构建，且保留可用回滚副本；
- 所有任务相关自动化验证通过，任何仓库既有非任务失败都被明确记录。
